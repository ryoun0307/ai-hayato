# 競馬予想テスト（過去レース）の計画

2026-11-19 にユーザーと決めた内容。作業する人（Claude）はこのファイルを最初に読む。

## 目的
- 「予想の手順書」で予想すると、どのくらい当たるか・回収率はどうかを、過去のレースで確かめる。
- 良い手順書ができたら、本番のハヤト（`index.html` の競馬予想）に組み込む。
- Opus と Sonnet のどちらが良いかは、おまけ程度の確認。

## 本番との関係（混同しないこと）
- 本番：GAS（`gas/keiba.gs`）が出馬表をスプレッドシートに保存 → 前日に仮予想、当日（発走前）に馬体重などを取り直して最終予想。ハヤト（Claude API・Opus）が予想。1日4〜5レース。
- テスト：**このパソコンの中だけ**で行う。GAS・スプレッドシート・ハヤト・API は使わない（料金ゼロ、Pro プランの枠内）。
- スプレッドシートと GAS の設定は、テストのあと、本番の前にユーザーと一緒にやる。

## 進め方の約束
- 予想は **Sonnet** で行う（Claude Code のこのセッションで、Pro プランの枠内）。Web 検索は使わない。
- 本番では Opus を使う予定。余裕があれば、数レースだけ Opus でも予想して、同じ馬を選ぶか比べる。
- ユーザーはエンジニアではない。日本語で、専門用語を言い換えて説明する。
- 区切りごとに止めて、ユーザーの OK をもらってから次へ進む（下の「段取り」の ★）。
- ファイルはすべて `keiba-test/` に置く。dev ブランチにコミットし、区切りで `git push origin dev`。

## データ（JRA 公式・確認済み）
- レース結果の開催一覧：`POST https://www.jra.go.jp/JRADB/accessS.html`、`cname=pw01sli00/AF`（Shift_JIS）。
  - 各日・各場のレース結果一覧の CNAME：`pw01srl10{場コード2桁}{年4桁}{回2桁}{日2桁}{日付8桁}/xx`
  - 各レース結果の CNAME：`pw01sde10{場}{年}{回}{日}{R2桁}{日付8桁}/xx`
  - 場コード：05＝東京、08＝京都（`gas/keiba.gs` の VENUES と同じ）
- レース結果ページにあるもの：着順・枠・馬番・馬名・性齢・斤量・騎手・タイム・着差・通過順・上がり・馬体重（増減）・調教師・単勝人気、払戻金（単勝・複勝・馬連・ワイド・3連単など）。
  - **当時の単勝オッズの数字は無い**（人気の順番だけ）。最終予想ではオッズの代わりに人気を使う。
- 各馬の成績ページ：`GET https://www.jra.go.jp/JRADB/accessU.html?CNAME=pw01dud...`（結果ページの馬名リンク）。過去の全レースが日付つきで載っている。
- JRA に負担をかけないよう、1回読むごとに1秒ほど待つ。robots.txt は全許可、私的使用の範囲。

## 対象レース
- 2026年10月〜11月（10/4〜11/15）の **東京・京都** の全レース（約300）。まず 150〜200 レースを予想する。
- 新しい時期を使う理由：AI が結果を知っていると、テストにならないため。
  - 最初に、Sonnet がこの時期のレース結果を知らないことを確かめる（数レースの勝ち馬を聞いてみる、など）。

## 結果を知らない状態を守る（いちばん大事）
- 予想に渡すデータは「そのレースの発走前に分かっていたこと」だけにする。
  - 各馬の過去4走は、成績ページから **そのレースの日付より前のレースだけ** を使って組み立て直す。
  - 結果ページの着順・タイム・着差・通過順・上がり・払戻金は、予想に渡すデータに入れない。
- 予想するときは、答え（結果）のファイルを読まない。

## 予想の2段階（本番と同じ）
- 仮予想（前日の夜の想定）：出走馬・枠・斤量・騎手・各馬の過去4走・血統（取れれば）。馬体重と人気は渡さない。
- 最終予想（発走30分前の想定）：上に加えて、当日の馬体重（増減）と単勝人気。

## 予想の手順書（ユーザーに見せて OK をもらう）
- 各馬を項目ごとに5段階で評価：近走の成績、距離の向き不向き、コース・馬場の向き不向き、騎手、休み明け、枠、展開、（最終予想のみ）馬体重の増減。
- 評価から各馬の勝つ見込み（%、レース内で合計100%）を出す。
- 印：◎○▲△△（5頭）と自信度（A/B/C）。
- 項目ごとの評価も記録する（外れた理由をあとで調べるため）。

## 買い目（ユーザー了承済み・1点100円）
- ◎の単勝・複勝（各1点）
- 馬連ボックス：◎○▲△（1頭目の△）の4頭、6点
- 馬連流し：◎から ○▲△△ へ、4点
- 3連単：◎1着固定、2・3着は ○▲△△ から、12点

## 答え合わせ
- 実際の払戻金で、券種ごとに「払った金額・戻った金額・回収率」と的中率を出す。
- 比べる相手：「1番人気を買っただけ」（同じ券種の組み方を人気順で作ったもの）。
- 仮予想と最終予想を比べる（馬体重・人気で良くなったか）。
- 自信度ごとの成績も出す。
- 回収率が100%を超えなくても、そのまま正直に報告する。48〜200レースでは運の影響が大きいことも伝える。

## 段取り
1. JRA から過去レースのデータを集める道具を作る（このパソコンで動くもの）。
2. 試しに数レース分を集め、データが正しいか確かめる（特に、過去4走にそのレース以降の成績が混ざっていないか）。
3. ★ 予想の手順書を作り、ユーザーに見せて OK をもらう。
4. 予想の記録と、答え合わせ（回収率の計算）の道具を作る。
5. ★ 1〜2レースだけ試しに予想し、ユーザーに流れを見てもらう。
6. ★ OK が出たら、150〜200レースを数日に分けて予想する（Pro プランの上限に気をつける）。
7. 答え合わせをして、結果をユーザーに分かりやすく報告する。手順書の直し方も提案する。

## ユーザーの決定（2026-11-27）：メインレース・重賞は外さない
- 「買うレースを絞る」（案2など）を採用しても、**重賞（GⅠ・GⅡ・GⅢ）と各場のメインレース（11R）は、条件に合わなくても必ず予想する**（「見送り」にしない）。
- 絞り込みは「外れにくいレースを選ぶ」ための目印として使う。メインレースは、条件に合わないときは「堅さ：荒れそう（絞り込みの条件外）」と添えて予想する。
- 案2の確認（11月分＋週末分）は、結果を見る前に決めた定義（案2_買うレースの条件.md）のまま行う。そのうえで、メインレース・重賞の成績は別に数えて添える（採用の判定には使わない）。
- 今の PC のシステム予想（weekend.ps1）は全レースを予想しているので、今のところ変更は不要。
